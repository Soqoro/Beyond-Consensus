## MedQA scope and blocker

No MedQA source or approved access receipt was found in the inspected repository. No cache, remote benchmark or credentials were accessed. The [disabled pilot packet](../outputs/next-results-preparation/MEDQA_PILOT.disabled.json) therefore has no invented revision, hash, selected IDs, bundles or rights conclusion. This does not block MATH.

Required source is the authors' English four-option **development** split, or a source-verified equivalent. Intake requires an explicit local-read receipt with version/artifact/hash and terms reference. Stable dataset ID, or frozen dev/row identity, determines ranking by `SHA256(canonical([policy,id]))`, then ID. Format eligibility uses question/options only; the first twelve eligible IDs are frozen once, and rejected-format rows are retained. Gold values do not select sources. A source-file hash changes if gold changes, but selected public IDs do not.

All four original option texts, including the unmarked correct candidate, remain public in original A/B/C/D label order. Correct-label metadata, identified gold text and rationales never enter planner/worker inputs. Duplicate text without an authoritative index produces unknown grading rather than a first-match guess. A valid index disambiguates duplicates. Conflicting index/text is unknown.

Terminal JSON has `justification` first and one `option_label` last. Grading accepts exact A/B/C/D only, with **no normalization or prose extraction**. Wrong valid labels are incorrect; malformed/extra fields are structurally invalid; unavailable mapping is unknown. This is exam-answer agreement, not clinical reliability or certification of intermediate reasoning.

The planning function makes at most twelve one-shot metered requests using the existing simple schema. Invalid or unsupported outcomes remain in the batch; uncertain accounting halts it. Actual review requires one complete human decision batch, preserving raw plans and reviewer-authored contract edits separately. The reviewed task graph may be sequential or singleton. No padding or forced edges. The worker packet then freezes up to three distinct n=4/K=2 source sets before prices, preferring disjoint sources and disclosing overlap. Only fixed base A/direct C are admitted in this pilot. Fresh unique profiles are medical-domain observations, never MATH prices. Bounds are ≤24 profiles, ≤240 evaluation calls, ≤30 evaluation sessions, plus ≤12 planning calls (≤276 overall). Actual graphs reduce these limits.

Because no real source or plans are available, MedQA's **live planning release and concrete post-review worker release remain unbound**. Offline injected planner and full mocked profile/selection/clean/all-owner execution are implemented and tested. The existing launch wrapper can only be bound after the source/tokenizer/scheduler scope and reviewed contracts exist; this report does not claim a runnable approved MedQA GPU campaign. Human review occurs after the planning allocation ends, not while a GPU waits.
